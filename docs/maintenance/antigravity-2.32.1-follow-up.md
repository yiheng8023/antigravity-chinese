# v3.3.48：完整组件漏项复核

## 问题与来源

2026-11-14，用户指出 3.3.47 仍漏译快捷键提交说明、置顶切换，以及旁路提问、选中菜单、相对时间、登录入口和自定义扩展导航。这说明上一轮覆盖了部分新功能名称，但文案清点没有覆盖完整组件；已通过的词库断言不能证明未纳入清单的文字已汉化。

再次核查 [官方更新日志](https://antigravity.google/docs/changelog/)，桌面仍列到 2.32.0，未单列本机 2.32.1；扩展仍为 1.12.0。本机 Windows x64 前端 SHA-256 为 `4c0a1ff5659e7dd92e6ad249a386c0dbce2c8e94b88522a2f366ff20b397081e`，与上一轮一致，因此本轮是补查和内容边界修复，不声称上游另有更新。

## 完整组件与边界

- 从实际前端静态脚本提取并审查命令名称、设置标题/说明、按钮/属性、菜单、空/错误状态等，扩展至插件详情、文件界面、旁路提问、概览、选中菜单和导航。分支判断、样式、代码及标识字段不作为待译 UI。清单保存 1052 条需汉化文案和 45 项保留或组合处理决定；它是这些组件的检查下限，不是全部产品的覆盖率。
- 补齐快捷键说明、编辑/重置提示、脚本保存、浏览器下载规则、语音、账号、插件和其他固定 UI 文案。型号、品牌、命令、路径、示例、技术枚举保留。语法碎片不盲目全局翻译；可识别的完整动态短句用窄规则保留插值。
- `Side Question(s)` 统一为“旁路提问”，`Ask /btw` 保留 `/btw` 命令。旁路提问的用户问题和回答保留原文，仅固定标签与思考状态汉化；同词正文有负例。
- 紧凑时间仅在实际时间控件中转换，如 `1mo ago` 显示“1个月前”。正文、Markdown 和普通段落中的同字符串保持原样；动态更新、节点移动后恢复源文本均有回归。
- 在实机确认 `/customizations` 路由与首个面包屑的实际结构，仅汉化此路由的固定首页标签。后续插件名、其他路由上的同名项目继续保护；路由切换复用节点时重新判定并恢复原文。
- `Go to Accounts`、`Commands` 等客户端操作和栏目汉化；插件介绍、README、建议提示词、技能描述和 `/gdocs` 等标识沿用作者内容保护，不按维护者的安装清单扩充翻译。

## 防漏检查

`test/fixtures/app-2.32.1-ui.json` 保存提取范围、前端哈希、审查分类和保留理由；`tools/ui-inventory.js` 将它接入回归。删除原先遗漏的提交说明会使测试失败，替换上游输入也会触发重新审查要求。提供官方 bundle 时校验哈希和记录文本的存在；不提供时仅核对已保存清单与词库。该工具不解析新的组件，也不以新词库反推上游清单，哈希变化须重新提取、审查。

贡献指南和诊断技能同步加入完整组件清点步骤，避免把用户截图当作全部验收清单。双语 README、生成词库与版本同步为 3.3.48。
