# v3.3.50：设置页掉帧与扫描调度

## 反馈与来源

2026-11-17，[用户反馈 #8](https://github.com/yiheng8023/antigravity-chinese/issues/8) 报告 Windows 11、Antigravity 2.32.1、汉化 3.3.49 在开关设置和切换左侧栏目时掉帧。反馈中的同机替代方案对照是主观观察，没有性能 trace；祖先链重复判定是待验证假设。缓存排除部分的前后陈述不一致，未将它作为定论，也未按反馈建议执行第三方安装器或删除用户缓存。

核查[官方更新日志](https://antigravity.google/docs/changelog/)后，最新桌面记录仍为 2026-11-13 的 2.32.0，未单列本机 2.32.1。本轮不声称上游发布新版本。

## 复现与原因

本机 Windows 11 10.0.26300 x64、App 2.32.1，通过本地调试连接操作固定的设置入口、外观、快捷键、通用和关闭按钮，记录 `requestAnimationFrame` 间隔及 `PerformanceObserver` 长任务。不采集屏幕、用户正文或网络请求。

在 3.3.49 下，对一棵已翻译、含 2698 个后代元素的实际设置树再扫描，仍耗时约 285 ms；临时方法计数记录约 74 万次 `getAttribute` 和 48 万次 `matches`。这是实际运行时热路径的测量，不是单独测试字典匹配的推断。回归 fixture 用 24 层包装和设置行将其缩小：745 个元素触发 209970 次选择器调用。同时复现了 650 个新增兄弟节点只译 500 个，以及单个 1200 行子树在一帧内全部递归的问题。

主要放大因素是每个元素和文本节点重复读取祖先链的 DOM 保护条件；新增节点中包含重叠父子树时又重复扫描。原来的批次按根节点计数，不能限制一个大设置子树的同步耗时。悬浮补查和周期补查也存在同步遍历路径。

## 修复

- 每个同步扫描片段内用 WeakMap 复用元素事实与判定结果，父元素已知的模式直接传给其文本节点。缓存在片段结束即释放；不跨渲染、节点移动、路由或下一帧保存内容归属结论。
- 异步扫描按实际 DOM 节点推进，每片段最多 200 个节点并设 6 ms 软时间预算。一个根有数千后代时也会让出下一帧；单个 DOM 操作本身不能被此预算抢占。
- 合并同一队列中重叠的父子根；超过 500 个待处理根时合并为分帧文档扫描，保留尾部。已移除的节点跳过，避免扫描失效页面。
- 悬浮与周期补查使用同一分帧队列；显式诊断 API 仍可同步扫描。每个片段只断开/重连观察器一次，保留断开前已排队的渲染器记录；动态属性加入队列。
- 保留所有内容边界、源文本恢复和后续作者写入保护。没有改词库、安装/还原算法、Swarm 独立运行时、协议、权限或插件内容。

## 同机测量与限制

采样数据及候选运行时哈希保存在 [`test/fixtures/settings-performance-2.32.1.json`](../../test/fixtures/settings-performance-2.32.1.json)。英文原版通过项目已有还原流程加载相同客户端的纯净备份；没有清理缓存。每组依次打开设置、切外观/快捷键/通用，再关闭；每个动作留出 650 ms 的观测窗口，长任务可能延长实际窗口。

| 指标 | 3.3.49 | 英文原版 | 修复候选 |
| --- | ---: | ---: | ---: |
| 对应打开采样的最大帧间隔 | 450.1 ms | 149.9 ms | 150.1 ms |
| 关闭采样的最大帧间隔 | 33.2 ms | 53.5 ms | 43.4 ms |
| 2698 元素热扫描，含方法计数开销 | 284.9 ms | 不适用 | 30.0 ms |
| 上述热扫描的 `matches` 次数 | 482047 | 不适用 | 15099 |

修复版另做三轮热态开关和切页：打开峰值为 69.9–73.3 ms，关闭为 30.0–40.0 ms，所测切页为 16.6–40.0 ms。英文原版同样存在宿主渲染长任务，不能把整个窗口的峰值都归于汉化，也不能用单机少量样本承诺所有设备、所有栏目均无掉帧。旧版关闭和已访问栏目在部分热态采样中本来就较快，未声称每个动作都得到同等改善。

最初一次尚未稳定的采样和失败的测量脚本调用未纳入表格。临时计数方法均恢复，调试窗口关闭后页面内采样器随之释放；固定字段的性能采样不是完整业务验收或所有用户环境的回放。

## 验证与影响面

`node --test test/test-runtime-performance.js` 新增四项回归：热扫描选择器调用量、650 个新增兄弟节点不丢尾部、大子树分帧，以及让出帧后重新判断已移动节点的内容归属。测试首先在 3.3.49 上复现前三项失败，再验证修复；现有 42 项内容边界回归继续通过。

共享运行时同时交付桌面 preload 和 VS Code Webview。扩展仍为 1.12.0，不声称本轮在 IDE 中复现了用户的设置页掉帧。Swarm 具有独立限定运行时，本次未改变其来源匹配、词库或后台服务。macOS/Linux 的范围为自动化回归，未做本轮实机性能验收。原版 ASAR、扩展备份和用户选择的全局插件须保留，发布前按贡献流程完成全套测试及目标提交的跨平台 CI。

本地完整 `npm test` 通过：13 个测试入口，包含 534 项文案断言、34 项综合回归、42 项内容回归、4 项性能回归、13 项 Swarm 回归、39 项 ASAR 生命周期检查及 45 项一致性检查。主词库保持 4541 条精确词条和 396 组规则。使用 `AGY_TEST_RUNTIME` 指向提取出的桌面安装脚本和扩展实际 `i18n-bundle.js`，分别执行 42+4 项回归，均通过；两份交付脚本均包含与源码一致的共享运行时。

英文原版还原和最终重新安装均使用显式 ASAR 路径，隔离 fixture 的全局插件目录。纯净 ASAR/扩展备份、全局社区插件和内置 Swarm 源文件哈希保持；本机安装核对 347 个外置文件。测量窗口正常退出后，核对并关闭其残留辅助进程，再无调试参数正常启动客户端。原先 11 个导入辅助进程保留，调试端口已关闭；本轮没有启用屏幕捕获。
