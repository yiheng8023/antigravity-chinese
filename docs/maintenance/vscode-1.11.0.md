# VS Code 扩展 1.11.0 维护记录

- 日期：2026-11-06；项目版本 v3.3.38，Windows VS Code 1.145.1、Google Antigravity 扩展 1.11.0。
- [官方更新日志](https://antigravity.google/docs/changelog?tab=extensions&ide=vscode)：1.11.0 发布于 2026-11-02，含 5 项改进、8 项修复。本机随扩展提供的 `CHANGELOG.md` 指向此页面，本次读取完整目标版本条目。

## 诊断与处理

本机扩展注册目录和 CLI 清单均为 1.11.0，汉化标记、词库、代理文件均缺失。更新覆盖了本地补丁，这是主体界面恢复英文的直接依据。原有四参数 `renderWebviewHtml(a,b,c,d)` 仍存在，现有注入器可安装到真实副本，无需改动注入签名。

同时发现 12 个命令标题和 4 个设置说明没有匹配当前词库。新增文案明确区分当前文件与所有文件的更改审查范围，补齐评论、菜单、焦点、更新日志入口，以及端口、心跳、跨轮次审查和评论设置说明。另对编译后原生 UI 对象的静态双引号 `label`、`tooltip`、`placeHolder` 字段做有限翻译，保留 Codicon 前缀、命令 ID、路由值和动态账号数据。

## 验证

- 真实 1.11.0 的 `package.json`、`extension.js` 副本完成安装、重复安装及逐字节一致还原；原版脚本 SHA-256 为 `e2a86df5cc44ddbb8fa1fab3027458bdf0fedb150ca2a73ff67fb92b3c77dec3`。
- 核对全部 30 个命令和 11 个设置/弃用说明字段；设置默认值及命令 ID 保持不变。
- 执行真实渲染方法的注入前缀，通过隔离的本地 HTTP 后端和代理加载 HTML，再用生产运行时验证中文 DOM，查询参数保留。该检查不等于真实 VS Code Webview 全流程验收。
- 新增命令范围与菜单负例先在旧实现上失败，修复后通过；覆盖路由值不误翻、Codicon 保留、命令不变及原件还原。
- 本地 `npm test` 通过：380 条黄金语义断言、31 个边界回归用例及 45 项静态一致性检查。分层词库与两个生成词库、根包与社区插件版本及双语文档已对齐。
- 本机 1.11.0 已安装 v3.3.38 补丁，备份与原版哈希匹配，注入词库与最终源码一致。新建本项目的 VS Code 验收窗口，确认实际 Webview 的“新建会话”和输入提示、原生菜单的“聚焦面板”“打开更新日志”等中文文案；未执行审查、登录或设置修改。验收窗口已正常关闭。此前打开的其他窗口需要重新加载才能载入新脚本。
- 本次仅处理 VS Code 扩展；桌面 ASAR、用户可选社区插件和账号/安全设置均不作为安装目标。桌面既有验收依据保持历史范围，见 [2.29.0 记录](antigravity-2.29.0.md)。

扩展每次更新均可能覆盖本地补丁，需重新运行 `node cli.js install:vscode` 并重新加载 VS Code 窗口。词库或接口是否需要增量适配，应以当次官方日志、源码和副本验证判断，不能把所有失效都归因于同一种原因。
